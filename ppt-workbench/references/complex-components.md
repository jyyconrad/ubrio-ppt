# 固定结构，替换数据的复杂组件库

用于高密度业务汇报中的矩阵、时间轴、横向卡片、关系网络、金字塔、雷达和复合图表。32张参考图是组件组合的视觉基准；每个组件同时提供业务用途、固定几何、数据字段、容量和必要关系。运行时替换数据，不重新手画形状或临时决定连线。

## 先判断关系，再选组件

| 要回答的问题 | 优先组件家族 | 必要输入 |
| --- | --- | --- |
| 哪些问题等权比较，各自怎样诊断 | 诊断矩阵、决策矩阵、实验矩阵 | 象限/类别、轴含义、事实、假设、动作或门禁 |
| 什么时候做什么、交付什么、何时退出 | 三阶段路线、七阶段轴、成长/人才链 | 阶段、时间、动作、工件、责任、退出条件 |
| 一组结果怎样同时比较 | 五项横卡、三工具双量化、九项指标 | 指标、口径、前后/目标、期间、样本和限制 |
| 一个系统怎样产生结果 | 一库三平台、屋顶四层、输入结果网络 | 节点职责、接口/边清单、方向、Owner、结果和护栏 |
| 反馈如何增强、学习怎样回流 | 铁三角、飞轮、学习循环、双协同回路 | 节点动作、输入输出、反馈方向、判断与分支 |
| 哪里出现偏差、怎样找原因和改正 | 六图看板、五层诊断、WBR、根因树/鱼骨 | 同口径序列、目标、偏差、解释状态、责任和复核 |
| 多维差距在哪里 | 原生雷达、五维行为对照、评分卡 | 同量尺维度、系列/选项、评分口径和来源 |

先用`scripts/svg/build_component.py --list`按问题和关系发现组件，再`--describe 组件id`读取字段与容量。实际打开对应原图或已渲染的组件样例，判断输入是否足够。仅有“蓝色、高密度、专业”不能决定组件；缺关系或证据时回材料，不能用示例事实补洞。

## 数据接口

组件目录在`assets/components/blue-dense/*-components.json`。`fields`指出组件依赖的数据记录；`--describe`导出的`data_contract`是调用方实际需要的JSON结构，已去掉坐标、尺寸、图标、颜色、字号等固定布局字段。`box`是固化边界，业务输入不用提供坐标。接口要求完整业务字段和固定数组容量，缺项或额外布局字段会报错。普通任务只使用显式`--content`；`--example`用于用户授权的合成演示。

生成时，在同一输入顶层填写`evidence_context{period,population,source,limitation}`，分别保留完整期间（含年份）、样本、来源和限制。它在固定组件下方独立显示两行口径，图形几何和字号保持不变；不把这些信息挤进每张卡的一行说明。四项均为非空业务文字，缺失说明、额外布局字段或超容量会报错。不适用或未知的口径明确说明，不能补造。授权`--example`显示合成期次和示例来源；真实任务使用自己的口径。

```bash
python3 scripts/svg/build_component.py --describe rd-five-metric-result-row
python3 scripts/svg/build_component.py \
  --component-id rd-five-metric-result-row --content results.json \
  --output-dir components/results --render
```

产物包含`content.json`、`source.svg`、`native-data.json`、`component-report.json`和可编辑`page.pptx`。组件单独输出时以原参考的字号和尺寸放在16:9白画布中央，便于复制到汇报页；不把长条组件放大到巨大自定义幻灯片。SVG结构是DrawingML，数据图和表是原生对象。不要把SVG或PNG作为整张位图贴入PPT。

`--describe`给字段职责和容量；只在显式`--example`时展示合成值。选中组件以外的业务字段使用中性空值并被排除，不继承其他模块的默认事实。组件从同一受控构图实现取得结构，避免独立样例与整页版式漂移。选中区域的非空文字超出组件边界，或超过构图声明的正文行数，会明确报错；先调整表达或选择合适变体，再生成，不能截掉业务内容。`excluded_boundary_elements`只记录跨区/未选对象的排除，仍须核对是否漏了连线或图标，不能以元素数量通过代替视觉检查。

已有目录声明的原生图表、表格数量也在组件抽取时核对，不能把四象限只剩两张表的文件当作成功。最终看图仍要核对全部维度文字、每组节点、连线和表格行，数量检查不能发现底板覆盖或字间碰撞。

数据替换保持builder产出的字号、几何和必要关系，不后改内部SVG来处理某个长值。五项横卡的指标名、主值和底部说明各为一行；较长前后值可把共同单位移到指标名或说明，例如`97.2→99.1`配`履约准时率（%）`，两个精确值与单位都保留。仍超容量时明确失败并调整表达；固定结构修补由维护者统一实现，不算业务数据调用。

## 组合接口

参考整册使用[前置校验制作入口](reference-deck-entry.md)；32页是同源组合样例，仍须以最终预览核对原图。新页面可将多个独立组件放入明确的区域，数据和位置分开：

```json
{
  "width": 1280,
  "height": 720,
  "instances": [
    {"id": "results", "component_id": "rd-five-metric-result-row", "x": 60, "y": 390, "data": {}}
  ]
}
```

上例仅说明组合格式，`data`必须填写完整，空对象不会生成。运行`build_component.py --composition composition.json --output-dir page --render`。实例ID必须唯一，原生槽会自动加实例前缀，重复使用同一组件也不会覆盖另一组数据。组件保留固定尺寸，超出画布会报错；选择合适变体或调整区域，不能拉伸图形、缩字或删除关系来塞满。

组合输入在顶层提供同样的`evidence_context`，作为全页证据口径；各实例的`data`仍只有组件业务字段。

每页仍需要一个主观点、金标page spec及整册合同。标题给判断，组件栏题定义证据角色，节点标签压缩重复字段，正文给事实/解释/动作，数值带口径，页底推出行动或取舍。组件组合应回答同一问题，不能把无关图形拼成高密度外观。

## 重要边界

- 原生雷达各维度必须同量尺；不同单位不能放同一雷达。百分数输入与格式对应，0.67配百分数格式，67配文字后缀。
- 客户体验雷达的三系列按“目标/理想、当前/本期、对照/试点”排列；固定样式填充第二系列，名称仍从每项name读取。该参考组件固定0至5分量尺，非有限值或超界值明确报错；其它量尺须选合适图表。点值不逐个铺在顶点，避免与维度/轴刻度重叠；精确数值保留在原生工作簿与输入数据中。
- 原生表格保留列语义、宽度、表头/首列配色和行高；WBR的微趋势与表格各自可编辑。
- 六图看板的微图分类和目标分类最多3个显示单位：汉字计1，ASCII字符约计0.56；例如`Q1`、`9月`、`目标`、`参考值`。正文动作不能当作时间分类。超过容量会在编译前报错；改成同义的简短分类，保留期间和单位。相邻数据标签由原生图表错开位置，精确数值仍保存在工作簿，不手绘数值或删掉点值。
- 输入结果网络必须给稳定节点ID及边清单，不能靠模型猜连线。财务终值在一条长框中收口，不能复制成额外一层平行结果。
- 鱼骨是相邻新增型：32张图可见根因树和五层诊断，没有完整标准鱼骨。该组件响应用户新增需求，不冒充某张图的直接复刻；原因均按假设验证。
- 同版式任务保持参考几何；普通任务按内容关系选择组件。两个分支都保留证据边界，不挪用原图或默认客户事实。

## 验证

1. 替换数据前后，对照`content.json`及最终文字、原生工作簿和表格，确认新数据实际进入对象，没有旧值泄漏。
2. 检查节点/行列数、方向、回流、分支、目标线、字体、数字焦点及来源；数据量超出容量先压缩表达或换变体。
3. 运行DrawingML预检和`inspect_pptx.py`，再渲染并实际读取最终预览。32参考组合还须逐页与原图比较。
4. 分别报告对象、内容、预览和PowerPoint编辑往返。编译成功和组件目录齐全不证明独立使用或视觉保真已经通过。
