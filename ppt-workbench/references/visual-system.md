# 全局视觉系统与逐页视觉简报

制作新整册或调整整体风格时读取本文件。只改少量文字或数据时，沿用已有模板和视觉规则，不需要重做整册规划或额外出图。用户参考图和已验证样例优先，先提取可复用规则，再补足本次内容需要。蓝色高密度中国式汇报须接着读 [包内图片与复合页型](blue-dense-report.md)，选择具体骨架、打开对应图片并执行逐页对照；本文件的浅色面板示例不代表该风格的完成样页。

## 四步制作顺序

1. **内容骨架**：先锁定 `thesis`、`audience_decision`、`evidence_ladder` 和页序；逐页写 `title`、`primary_claim`、`key_message`、`proves`、2–3 个支撑点、证据边界和行动/决策。页面需要什么图表、表格、截图或图标，也在这一阶段写清。
2. **全局视觉系统**：在整册层面确定 `visual_system`，至少包括风格、字体层级、配色、间距、图标风格、图表风格和表面处理。正文页默认继承这套系统；留白用于分组和强调，正文的信息密度仍按页面族验收。用户给参考图时从图中提取区域网格、深浅层级、数字焦点和连接语法，而不只记颜色。
3. **逐页视觉简报**：每个正文页写 `visual_brief`，描述构图、视觉焦点、背景和元素位置；有需要再补光影和材质。它是制作和验收的中间合同，不是让模型自由发挥的口号。
4. **可编辑落地**：把内容骨架和视觉简报落实为文字、形状、原生表格、原生图表和受控图片对象，完成 `inspect_pptx.py`、预览和整册质量门。整页视觉样机不能替代可编辑正文；局部生成图片按 [图片用途与实现](generate/methods/image-owners.md) 使用，不冒充真实证据。

## Deck-level `visual_system`

多页任务的 `deck_manifest.json` 增加以下字段。这是一组 1280×720 画布上的示例值，按用户模板和已安装中文字体调整，不是唯一风格：

```yaml
visual_system:
  style_profile: "浅色商务汇报，证据面板与关系标注"
  typography: "微软雅黑；SVG 标题 40px/700，正文 24px/400，来源 16px/400"
  palette: "背景 #F6F8FB，正文 #334155，标题 #0F172A，强调 #2563EB，风险 #B91C1C"
  spacing: "画布边距 64px，面板间距 24px，面板内边距 20px"
  icon_style: "lucide 线性图标，同一显示尺寸 24px，同一线宽 2px"
  chart_style: "原生图表；灰色辅助线，蓝色主序列；类别和单位直接标注"
  surface: "白色证据面板，浅灰边框；正文无纹理、无投影"
```

这些字段可以是简短中文说明，也可以是更详细的对象。最低要求是每项都有明确取值，不能只写“高级感”“统一风格”。不使用图标、图表或阴影时可直接写“本册不使用”，不为填字段增加装饰。`style_profile` 只定义视觉语言，不改变事实、数据、标题、证据状态或页面结构。

仅改变风格时，调整字体层级、色板、面板表面、图标家族和装饰用量；保留事实、口径和主要信息关系，再按新字体度量重排文字、校验容量。封面、章节页可以有页面级变体，正文页默认继承整册 `visual_system`。表格和图表按信息关系选择：需要逐项查读或多维比较时使用原生表格，不能把所有数字强制转换成图表。

## Page-level `visual_brief`

正文页至少写清构图、焦点、背景、元素位置四项。例如主观点为“先补齐交接证据，再扩大试点”的流程页：

```yaml
visual_brief:
  composition: "需求确认→实现→验收横向展开，缺交接记录处用断口标记"
  visual_focus: "实现与验收之间的断口及要补齐的测试记录"
  background: "浅灰底白色证据面板，断口周围留白以突出缺项"
  element_positions: "上方判断标题；中部流程；节点下挂记录；底部放负责人、行动和来源"
  light_shadow: "无；通过边框和间距区分层级"
  material: "纯色，无纹理"
```

视觉简报要能指导实现和复核：

- `composition` 必须与 `dominant` 的主导信息关系一致，并说明相连证据区如何布置；不能写“自由排版”或只写一个大卡。
- `visual_focus` 直接服务于 `primary_claim`，按页型突出判断、主证据、关键关系或待拍板项；写明具体对象，不只写“突出重点”。建议、目标和待核实项保留证据状态。
- `background` 和 `material` 不能降低正文、表格、图表标签或来源的对比度。
- `element_positions` 要说明关系和阅读顺序，不必写死每个坐标；坐标由页面方法和组件容量决定。
- 使用截图、AI 生成图或样机时，仍需在旁边保留可编辑的结论、标注、证据边界和行动；不能把整页渲染成单张图片。
- 只有新构图、参考样式不明确或复杂视觉资产需要探索时，才制作额外视觉样机；优先用实际可编辑样页验证密度和可读性。整页 AI 效果图仅作参考，照片、纹理或插画可按图片规则成为局部资产。

## 参考图组件

用户给了参考图时，复用组件语法，不复用其中的事实。箭头链的每一段写成 `process-step`：编号或图标加上一句，不只有阶段名。左右对照写成两块 `comparison-panel`，各有一句，不用一张表代替。证据卡写成 `evidence-panel`，文字要进入面板下半部，不能只贴在上沿。蓝色高密度参考的指标卡、根因链、阶段轴与底部推论有不同职责，可在同一页形成多区组合；按 [五种复合骨架](blue-dense-report.md#五种可组合骨架) 选取和复核。

画完对 `source.svg` 运行：

```bash
python3 scripts/svg/check_shape_picture.py --dominant 左右对照 --svg source.svg
```

`visual_brief_passed` 只说明简报字段写了。它不证明画面里有这些组件。`check_shape_picture.py` 目前只对部分原有 `dominant` 做确定性几何检查；新增复合关系必须读最终预览，逐区核对参考结构。

## 验收

整册预检报告单独记录：

- `visual_system_passed`：静态预检是否记录了全局视觉系统的各项取值；
- `visual_brief_passed`：静态预检是否记录了每个正文页的构图、视觉焦点、背景和元素位置；
- `visual_review`：是否完成 100% 渲染目检、远距/三秒主观点检查和溢出遮挡检查。

静态报告注明 `validation_scope=declared_contract_only`；字段齐全不证明描述可执行，也不证明渲染器实际采用了这些值。制作时将规则映射到所选模板、page spec 或渲染器支持的参数；这些作者元数据不会自动改变渲染结果。目检时再核对与参考/样例的对应关系、字体与色彩一致性、证据可读性和实际落地效果。

当前金标 builder 的配色通过 `theme_id` / `visual_tokens` 落地，其中颜色键为 `background`、`surface`、`title_text`、`body_text`、`source_text`、`accent`、`warning`、`border` 等；背景对象另按 `deck-framework.json` 的合同设置。字体、字号、间距和布局仍须在实际 SVG/模板及原生 overlay 中落实并复核，不能因为填写了 manifest 就声称自动应用。

方法来源：[AI 办公小栈的四步 PPT 制作思路](https://mp.weixin.qq.com/s/RyZh7vcGb5DC4L6FQJGImw)，经中国式业务汇报的密度、参考复用和可编辑要求调整；不将每页出图、增加阴影或所有数字图表化设为默认动作。
