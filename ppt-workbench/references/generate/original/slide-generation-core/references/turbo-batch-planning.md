# 极速模式：批次规划与结果决策

本方法只适用于极速模式。它规定批次怎么划分、SubAgent 负责什么，以及主 Agent 收到结果后如何选择下一步。

## 批次规划

- 批次必须覆盖全部待生成页面，不重复、不遗漏，并保留全册叙事顺序。
- 优先把页面类型、结构方法和素材依赖相近的页面放在同一批，再根据复杂度控制批次大小。
- 高复杂页应减少同批页数；互相依赖的页面保持先后关系；已经开始的批次不重新分组。
- 每个批次写明页码范围、共同结构或素材依据、复杂度和成功标准。

## SubAgent 职责

- 每个批次只启动一个负责该批的 SubAgent；SubAgent 只负责本批次授权页。
- SubAgent 可在授权范围内决定页面处理顺序，但不能修改其它批次、启动后续批次或改变全册目标。
- 批内每页仍遵守单页的观点、证据、容量、可编辑性和视觉质量标准。
- 某页无法完成时，保留已完成页面，并在结果中明确失败页、原因、可重试条件和风险。

## 批次结果判读

- 主 Agent 只依据满足输出合同的批次结果做决策，不根据过程描述猜测完成状态。
- 批次结果摘要至少包含：批次编号、授权页、完成页、失败页、未完成页、证据或产物摘要、风险和建议动作。
- 批次执行期间，主 Agent 不接管同批页面；结果存在缺口时只处理未完成范围。

## 主 Agent 决策

**主 Agent 根据批次结果显式选择**，不得把批次推进交给 SubAgent：

- 没有前置依赖的批次可以并行启动；存在明确内容、素材或跨页承接依赖时，先完成前置批次再启动后续批次。
- 启动后不接管 SubAgent 已授权的页面，也不根据过程性描述推断完成；等待系统提供可验证的批次结果摘要。
- 参数或输入可修复时只修正点名问题；内部执行错误没有明确修复条件时停止原样重试并报告风险。
- 用户已经点名页面并给出修改要求时，只重开或修订这些页面，不改写整个批次计划，不重跑已确认页面，也不重新询问用户是否重做全册。

1. **重启当前批次**：适用于失败可重试、输入已补齐或失败范围可以安全缩小时；只覆盖未完成页。
2. **启动后续未开始批次**：适用于初始并行启动漏项，或某批存在明确前置依赖而此前未启动。
3. **跳过失败页**：适用于用户允许降级，且失败页不影响全册叙事和交付完整性；必须记录影响。
4. **停止**：适用于关键素材缺失、连续失败、结果冲突、质量不可接受或用户目标发生变化。

主 Agent 在选择前检查批次成功标准、失败原因、全册依赖和剩余风险。不能因收到“已结束”就默认成功，也不能在当前批仍有关键缺口时盲目启动后续批次。
