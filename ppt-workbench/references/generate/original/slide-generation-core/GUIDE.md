# slide_generation 主控 Skill

本 Skill 是当前页的主控 Skill，只提供可复制的页面判断方法。它按需进入上下文，**不默认全文注入**。阶段推进、状态迁移和确定性执行由代码负责。

目标是：**根据已有主题、逻辑结构、素材信息和大纲信息，编写当前指定页面的 PPTX，完成内容与结构设计并形成可落版的当前页 PPTX**。

## 输入合同

开始前确认以下信息；缺失项只在确实影响页面判断时补齐：

- 整套 PPT 的主题、受众、汇报场景、沟通目标与叙事主线。
- 当前页在大纲中的位置、页面角色、核心观点及与前后页的承接关系。
- 可用素材信息、数据口径、事实来源、案例、图片与品牌约束。
- 页面类型、信息密度、可编辑性要求及需要保留的原始内容。

## 单页表达原则

`slide_generation` 默认服务中国式业务汇报。页面展示逻辑应围绕一个核心观点，并按用户阅读习惯建立清晰阅读路径。

1. 标题必须是观点句，而不是宽泛主题词。
2. 一页一义：每页只证明一个主判断。
3. 数据佐证托住事实强度；观点佐证托住因果、机制、案例、政策或专家判断。
4. 正文优先形成“结论、证据、解释、影响、行动或风险”的闭环，至少覆盖其中三类。
5. 结论落点明确：读者看完后应知道接受什么判断、记住什么信息或采取什么行动。
6. 对内部测算、单一案例和能力示意明确标出口径，不把局部结论写成普适事实。

## 结构与证据规则

- 先写一句核心结论，再选择最能证明它的结构；不要先套模板再填内容。
- 优先使用对比、递进、因果、流程、时间线、矩阵、指标卡或“结论-证据-行动”等可解释结构。
- 每个核心论点绑定数据、事实、案例或来源；素材不足时，使用素材读取、素材补充或公开检索入口，不编造硬指标。
- 内容超出可读容量时，按“次要说明、重复论据、背景补充”顺序压缩；仍超载则拆页，不缩小到不可读字号。
- 图片必须承担背景氛围、正文证据或结构说明中的明确角色；证据型图片不能用生成图冒充事实。
- 照片、肖像、书封、真实场景、证据截图和复杂纹理必须由受控图片资产承载，不建议模型手绘 SVG 模仿。已有合适图片绑定时保留；来源或 overlay 失败时用相同图片 ID 修复或替换，不以删图绕过错误。
- 每页独立判断背景：deck / page-role 默认仅作兜底。有合适且不损害可读性的图片时优先考虑图片背景；没有合适图时使用纯色、纸纹或低干扰抽象 SVG，不强制每页铺图。

## PPTX 原生对象建模原则

建模顺序是：**用户需求 → 页面意图 → 语义原子 → 组合结构 → 页面对象**。

- 文本、数字、标签用文本框。
- 形状 / 线条 / 连接符承担底板、箭头、分割与关系表达。
- 图表、表格、独立 SVG、图片占位按最小可编辑语义拆解。
- SVG 适合承载结构、文字、形状、关系和低干扰抽象装饰，不承担照片、肖像、真实场景或证据截图的仿制。
- 组合实现优先保证标题层级、主视觉锚点、信息承载率和后续可编辑性，不复制参考图的表面像素。

## 质量覆盖路由

当前页的证据、最终文案、结构、容量、视觉、框架、来源与交付边界见 `references/current-slide-quality-scope.md`。代码 QA 只能覆盖稳定信号；观点是否成立、证据是否支撑结论、结构是否利于汇报仍需业务判断。

需要具体 SVG DrawingML 编写、图片落版或背景 override 方法时按需读取 `slide-authoring`，不要在本主控 Skill 里固化坐标答案。

极速模式下的批次业务决策见 `references/turbo-batch-planning.md`，该扩展不改变单页质量标准。

## 质量与失败条件

交付前确认：

- 标题是清晰结论，正文证据与标题方向一致。
- 阅读路径唯一且层级清楚，没有大面积无意义留白或信息拥堵。
- 关键数字有口径，关键事实有来源，假设与风险可辨。
- 页面对象可被继续编辑，照片、真实纹理、复杂光影只位图化必要的最小范围。

出现以下情况不得把当前页视为完成：核心观点不明确；关键证据缺失或相互冲突；内容超过页面容量且无法可靠压缩；必须使用的素材不可用；结构依赖未经确认的数字或结论。
