# Layout: Quadrant / 2x2 Positioning Matrix

## 使用判断

象限图用于解释“两个判断轴如何共同决定定位、优先级或行动取舍”，不是四块并列卡片。

适合：

- 竞品、方案、业务单元、客户群的二维定位。
- 优先级组合：影响大小 × 推进难度、收益 × 风险、价值 × 成熟度。
- 能力成熟度、市场空白、产品定位、资源投入组合、风险治理象限。
- SWOT/3C/PEST 时同时读取 `content-swot-3c-pest.md`。

不适合：

- 只想并列展示四类信息：改用 `layout-four-cards-grid.md`。
- 需要精确散点/回归/连续刻度：声明 `native-chart-slot`，不要手绘 SVG 数据图。
- 没有对象、证据或动作：先补内容，不画空四象限。

## 输入合同

生成前必须整理：

- `matrix_purpose`：本页要证明的业务判断。
- `x_axis` / `y_axis`：轴名、低端标签、高端标签、方向箭头。
- `quadrants`：四象限名称、解释、建议动作；名称来自轴语义组合。
- `points`：对象名、类别、相对位置、判断依据、可选权重。
- `focus`：重点对象、目标区、市场空白或迁移方向。
- `source_note`：数据、材料、专家判断或证据边界。

## 轴与象限规则

- 两条轴必须是可判断、方向明确的业务变量，如“开放性：封闭定制 → 开源开放”。
- 禁止写“好 → 坏”“强 → 弱”这类无判断维度的轴。
- x 轴默认从左到右表示更成熟、更高价值或更易落地；y 轴默认从下到上表示更高价值、更高成熟度、更高风险或更高复杂度。
- 如果“高”代表风险/成本，必须在轴名和象限解释中说明，避免把右上角误读为天然最佳。
- 四象限不能只叫 Q1/Q2/Q3/Q4，也不要只写“高高/高低”；名称要体现动作，如“优先投入”“攻坚突破”“快赢复制”“观察维持”。
- 每个象限至少有短名称、一句解释、一个动作或启示。

## 点位与收口

- 点位数量 3-8 个最稳；超过 10 个时保留关键对象，其余合并为类别或转表格。
- 重点对象直接贴标签；普通对象用短标签或编号，编号必须在图例解释。
- 标签优先放点位右上或右侧；靠边界时向内翻转，密集点使用引线。
- 重点点位可加外圈、光晕或短注释；不要给所有点都加外圈。
- 趋势箭头只画 1-2 条关键迁移路径，并写动作词，不作装饰线。
- 顶部标题写观点句；底部或右侧加 `insight-bar`，说明“投什么、避开什么、下一步做什么”。
- 证据不足时标注“根据当前材料判断”，不要编造百分比、金额、CAGR 或市场份额。

## BCG 增长-份额矩阵专属合同

BCG（波士顿/增长-份额矩阵）是象限图的一个**轴与象限语义固定**的特例，不能套用通用 2x2 或
SWOT 的合同。判断到 `bcg_matrix` 时按本节收口：

- 两轴固定，不可改名换义：
  - x 轴 = **相对市场份额**，高端在**左**、低端在**右**（经典 BCG 与常规左低右高相反，必须在轴标签写明方向，避免误读）。
  - y 轴 = **市场增长率**，低端在下、高端在上。
- 四象限名称与位置固定，且每格必须带资源动作：
  - 左上（高增长·高份额）= **明星 Star** → 持续投入、保住领先。
  - 左下（低增长·高份额）= **现金牛 Cash Cow** → 维持挤现金、反哺其它。
  - 右上（高增长·低份额）= **问题 Question Mark** → 选择性投入或验证后放弃。
  - 右下（低增长·低份额）= **瘦狗 Dog** → 收割或退出。
- 每个业务单元是一个**气泡**：位置由两轴决定，气泡面积可按营收/规模缩放（缩放规则写进图例）。
- 容量 **3~8 个业务单元**：超过 8 个气泡拥挤、标签打架，必须**拆页**（按事业群分页）或改
  `content_list` 表格呈现，不要硬塞进一页。
- 拿不到可比的市场份额/增长率数据时，退化到 `priority_matrix` 等轴可自定义的四象限，或标注
  “按当前材料定性判断”，**不得编造 CAGR、份额百分比或营收数字**。
- 顶部写组合层面的结论（“投什么、挤什么、退什么”），底部 `insight-bar` 给资源再分配动作。

## 密度与几何

- 先用 `deck_framework_snapshot.content_region_px` 或默认安全区确定 `region`。
- `matrix-region` 占主体宽度 60%-75%、主体高度 70%-82%，不能压成浅层小网格。
- `insight-region` 放右侧或底部；点位多时优先放底部。
- 双矩阵或矩阵+右侧依据卡片时，两块主体卡片一起增高，底边通常落在 `y≈544-584`，底部收口条落在 `y≈592-640`。
- 主体矩阵、双矩阵卡片或 `insight-bar` 必须延展到页面下半部；除 `source-note` 外，主要内容底边通常达到 `y≈608`。
- 象限底色要轻、分割线要细；点位和标签是主体。
- 标签字号不低于正文最低可读字号；长解释放右侧注释区，不塞进点位旁。
- 来源说明最多一句话，放内容区底部，不进入矩阵内部。

## 预渲染检查

- 两条轴是否有低/高端语义和方向箭头。
- 四象限名称是否由轴语义推导，而不是模板词。
- 是否至少 3 个点位或 4 个象限说明，且重点点有判断依据。
- 标签、图例、箭头是否避让，矩阵内没有文字重叠。
- 是否有结论条或右侧 insight，而不是只有坐标网格。
- 主体是否延展到下半部，主要内容底边是否达到 `y≈608`。
- 无证据时是否标注判断边界，且没有编造硬指标。
