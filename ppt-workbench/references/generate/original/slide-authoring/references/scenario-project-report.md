# Scenario: Project Report

## 内容说明

写进度、风险、阻塞、决策诉求和责任闭环。

除封面和目录外，项目汇报页不能停留在“进度、风险、计划”三类标签。每页至少放入：

- 一个结论判断：是否可控、是否需升级、是否影响验收。
- 两类证据：进度数据、问题单、排期表、验收截图、会议纪要或责任矩阵。
- 一个行动闭环：责任人、时限、交付物、验收标准或升级路径。

正文页常用标题：

- “当前总体可控，但两项风险需要升级处理”
- “关键里程碑按计划推进”
- “数据口径与资源排期是主要阻塞”

## 视觉说明

逻辑清晰，风险和决策诉求突出。普通页用浅底，风险页可少量使用警示色。

## SVG说明

优先布局：`layout-left-claim-right-evidence.md`、`layout-timeline-horizontal.md`、
`layout-problem-solution-benefit.md`。

高密度 SVG 页建议使用这些结构：

- 进度页：顶部 4 个指标 + 主体里程碑 + 底部倒排判断。
- 风险页：二维风险矩阵 + 触发条件 + Owner + 截止时间。
- 决策页：左侧项目判断 + 右侧 3 条诉求 + 决策后影响。
- 资源页：泳道甘特 + 右侧资源依赖，不要把 4 条工作流拉成空卡片。
- 问题/行动页：表格必须包含来源、影响、Owner、时限、状态或验收标准。

## 截图级 2 页金标示例

弱模型生成项目汇报时，优先照抄 `04-timeline.svg` 和 `08-issue-log.svg` 的结构，
再替换成用户真实素材。目标不是“好看卡片”，而是一页内完成判断、证据、解释、
影响和行动闭环。

更细的逐步复现手册见 `scenario-project-report-gold-pages.md`。当目标是复现这 2 页
内容充实的 PPTX 时，必须读取该文件，它包含读取顺序、区域坐标、视觉 token、
内容槽位、SVG 分组和转换失败修复规则。

第 4 页“验收总览驾驶舱”：

- 基础视觉：框架层浅灰背景、白色信息面板、深蓝主标题、正文深灰、来源文字浅灰、风险用红色。
- 结构：顶部 4 个进度指标；左侧领导结论；中部里程碑表；右侧趋势小图表；底部素材来源条。
- 必填信息：总体进度、主流程通过数、验收材料完成度、问题关闭率、证据材料、红色阻塞。
- 可见性：每个文字和图形都必须显式 fill，深蓝底使用白字，浅底使用深色字。

第 8 页“问题-证据-行动闭环表”：

- 基础视觉：左侧问题表格承载细节，右侧证据链解释为什么要升级，底部行动条收口。
- 表格字段：编号、问题、来源/证据、影响、Owner、时限、状态，至少 5 行。
- 证据链：来源、判断、动作、验收四段，每段写一句解释，不用口号。
- 行动闭环：红黄蓝状态必须绑定责任人、截止时间、交付物或验收标准。
