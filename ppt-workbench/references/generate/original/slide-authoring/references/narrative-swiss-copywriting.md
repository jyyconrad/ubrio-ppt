# Narrative: Swiss Copywriting

## 内容说明

Swiss 信息设计的文字不是"配文"，是页面的主视觉。它的稳定文案方法是"短判断 + 强对比 + 有归因"，不是复用某句现成标语。本文件给的是句式骨架、字数节奏、语气边界和失败检查，**不给固定话术**——任何模板句都要按当前页真实内容重写。

配合关系：网格与安全区读 `layout-swiss-core-grid.md`，标准结构骨架与容量读 `layout-swiss-standard-structures.md`，指标/账单/收束结构骨架与容量读 `layout-swiss-metric-structures.md`；本文件负责往那些骨架里填什么口吻的字、每类字段允许多少字、什么语气会破坏 Swiss 的克制感。

## 标题句式：判断句 / 动词句 / 数字句

Swiss 标题是页面的判断锚点，必须能独立成一句结论，不写名词短语或泛标签。三种可选句式：

- **判断句**：给出一个可被证据支撑的主张。适合陈述页、章节页、正文页。例：把"项目风险"改成一句"谁是当前主要风险 + 为什么"。
- **动词句**：以动作或机制开头，强调"做了什么 / 会带来什么"。适合行动页、方案页、能力页。
- **数字句**：标题直接嵌一个关键数字或倍数，把量级前置。适合有硬数据的封面、指标页、Why Now 页。

字数节奏（中文方块字视觉面积重，必须比英文更克制）：

- 中文主标题优先 ≤ 8 字一行；两行时每行 ≤ 8 字；任一行到 9-12 字就先改短标题，改不动才降字号，绝不靠缩字号硬塞。
- 标题越长、字号越受高度上限压制，越会失去"大字判断"的力量感；宁可把解释性从句移到副标题 / 来源注，也不要把两个论点塞进一个标题。
- 标题不能被 kicker、页码、章节号在视觉上压过——它们是辅助信息，标题才是锚点。

反面：名词堆砌（"销售增长"）、四字口号（"提质增效"）、"XX 主题分析"式题注。这类要按 `content-title-rewriting.md` 改成判断句后再进 Swiss 版式。

## kicker / eyebrow 小标签

kicker（章节英文引导词 / 编号 / 领域标签，如 `METHODOLOGY · 03`）是标题的从属信息，用来定位"这是第几章、属于哪个领域"，不承载论点。

- 功能单一：章节定位或分类，一到两段短语，不写完整句子、不写论点。
- 字数：中文 kicker ≤ 8 字；英文 / 编号型更短。它是节奏配重，不是第二标题。
- 语义层级：kicker 在标题**上方**（上下从属关系），不与标题并成左右两列——横排会让读者误读成两个对等信息。
- 一页最多一个 kicker 层级；正文卡片内部可省略 kicker，不要每个卡都挂标签制造噪音。

## 宣言页：语气与断句

宣言 / 陈述页（cover、section_divider、key_message）一页只放一句话，把论点压到极短、放到极大。

- 压缩到一句可讲的判断或口号，中文尽量 ≤ 12 字级别的短句；承载不了列表或数据（要数据支撑改走 Why Now / 指标页）。
- 断句服务朗读节奏：按语义单元换行，让每行是一个可停顿的意群，而不是按字数硬折。一句话拆成 2-3 行时，每行都应能独立读出重音。
- 只保留少量归因或署名（来源、时间、作者）做配重，不在宣言页堆解释段。
- 大字宣言靠"短 + 准 + 留白"取得力量，不靠形容词加码；一页宣言里最多一个强调点（一个词或一个数字变色）。

## 巨数配文：数字 + 单位 + 一句归因

巨数是数据页的视觉锚点，但裸数字没有说服力。每个巨数固定三件套：**量化值（含单位/倍数）+ 短标签 + 一句归因**。

- 量化值必须真实、可追溯；缺真实数据时降级为陈述页或卡片页，**绝不为凑版式编数字**（编造的对比数会被一眼识破）。
- 归因一句话回答"这个数说明了什么 / 从哪来"，不是重复数字本身。标签给维度名，归因给意义。
- 时间演化型（纵向指标时间轴）每节点是"年份/期次 + 巨数 + 短标题 + 描述"；论点递进型（三列递进）每列是"kicker + 一句论点 + 描述 + 列底巨数"；账单型（KPI ledger）每行是"巨数 + 标签 + 可选说明"。字段容量以 `layout-swiss-metric-structures.md` 的对应结构骨架为准。
- 同一页多个巨数时字号统一、锚定同一基准线，只用颜色标出最重点的一个，不用改字号或加粗制造层级。

## 对比 / 递进结构的文案骨架

- **双轨对照（Before/After、旧/新、A vs B）**：两侧文案必须同构——同样的 kicker + 标题 + 说明结构、同样的字数量级、同样的抽象层级。一侧写机制、另一侧写口号会破坏对照。恰好两项；差异点要落在"标题的判断"上，而不是靠说明段长度差异。
- **论点递进（三列 / 三支撑）**：三列并列且有方向性递进，末列是最重点论据。每列一句论点标题 + 一段描述（可配列底巨数）。三条论点要同层级、同句式；如果其中一条明显更弱，先砍掉换四卡，而不是硬凑第三列。
- **三支撑（一个 lead + 三证据）**：lead 必须是真判断句，三张卡承载**不同角度**的证据（数据 / 案例 / 机制），不是同一论点的三次复述。

## 收束页：行动导向语气

收束页（closing、每套 deck 仅一页）= 一句收束宣言 + 三条可带走结论。

- 收束宣言是把整套 deck 的核心判断再压一次的短句，语气偏"落地 / 确定"，不是重新展开新论点。
- 三条 takeaway 每条 = 编号 + 短标题 + 一行说明；短标题动词化或结论化，说明给"下一步做什么 / 意味着什么"。末条用唯一强调把重点结论收口。
- 语气朝行动或判断收敛，不要用开放式提问或抒情结尾冲淡结论。收束页不承载新数据。

## 语气边界：商务汇报口径 vs 营销 / 宣言口径

Swiss 素材天然带"宣言 / manifesto"腔调，但业务汇报必须克制。按场景切换口径：

- **商务汇报 / 项目复盘 / 经营分析**：标题给判断和归因，巨数带真实来源，收束给行动。禁止空洞形容词（"卓越""领先""全面赋能"）、禁止无数据的煽动式大字。宣言式大字只用于封面、章节页和一句核心主张，正文回到"判断 + 证据 + 行动"。
- **营销 / 主题宣讲 / keynote**：可以更大胆用宣言页、口号断句和情绪化标题，但仍守"一页一个论点、数字要真"。
- **文学 / 纪录片 / 读书分享**：不走本文件，改读 `content-literary-documentary-narrative.md`；那类页面允许意象和金句，语气边界不同。硬把业务 metric/action 塞进文学页，或把文学抒情腔塞进经营汇报，都是越界。

判断规则：先确认页面所属场景，再选口径；同一套 deck 不要在商务克制和营销煽动之间来回横跳。

## 文案密度与视觉结构的配合

- 宣言 / 陈述结构（cover、statement、section_divider）：极低文字密度，一句话为主，大量留白。密度过高会毁掉大字的力量。
- 卡片并列结构（四卡、六格）：中等密度，每格信息量相近；出现空卡、只有编号或只有泛标签时，先补内容或换结构，不要留半空格子。
- 指标 / 递进 / 账单结构：密度由巨数主导，配文精简到"标签 + 一句归因"；描述超容量先改写压缩，不缩字号硬塞。
- 收束结构：低到中密度，宣言 + 三条短结论，不堆长段。

密度与结构不匹配（如把六格的信息量塞进陈述页，或把一句宣言摊成四卡）是最常见的文案-版式错配。先按内容形态选结构（读 `layout-swiss-svg-drawingml.md` 的结构选择），再按结构定文案密度。

## 失败检查（反模式）

进入渲染前逐条自检，命中即改：

- **口号堆砌**：整页只有"聚焦增长 / 协同赋能 / 提质增效"等泛标签，无判断、无证据、无行动 → 改判断句 + 补 2-3 条事实/数据/案例 + 一句行动收口（详见 `anti-pattern-low-density-slogan.md`）。
- **空洞形容词**：靠"卓越 / 领先 / 全面 / 深度赋能"撑标题，没有可验证内容 → 换成带对象和量级的具体判断。
- **数字无归因**：巨数只有数值没有单位、标签或来源说明，读者不知道它意味着什么 → 补齐"量化值 + 标签 + 一句归因"三件套。
- **编造数据凑版式**：为用 KPI/指标结构而编数字 → 无真实数据就降级为陈述页或卡片页。
- **标题超长压占内容区**：标题拖到三行、字号被高度上限截小 → 先改短标题或把从句移到副标题 / 来源注。
- **kicker 越权**：小标签写成第二标题或承载论点 → 收回到"章节定位 / 分类"的单一功能。
- **口径混用**：商务汇报页出现营销煽动腔，或文学抒情句塞进经营汇报 → 按场景切回对应口径。
- **修辞套路化（AI 味）**：「不是 A，而是 B」句式反复出现、热词名词（赋能/抓手/闭环/底座/飞轮/护城河）堆砌、破折号与段尾万能总结滥用 → 读 `anti-pattern-ai-flavor.md` 做综合判定与替换；本文件的句式骨架按真实内容重写后不应残留这些套路。

## 禁止项

- 不照抄任何整页文案或固定话术模板；所有句式骨架都要按当前页真实内容重写。
- 不为凑版式或凑对称编造数字、案例或来源。
- 不用形容词密度替代信息密度。
- 不把本文件的文案方法用到非 SVG 版式路线；Swiss 页面文案落地一律配合 `layout-swiss-svg-drawingml.md` 的 SVG DrawingML 结构骨架。
