# Content Density Contract

## 内容说明

中国式业务汇报正文页必须覆盖 `claim/evidence/explanation/implication/action_or_risk`
中至少 3 类。不能只写标题、编号和形容词。

对应中文结构是：观点、证据、解释、影响、行动/风险。正文页至少命中其中 3 类。

每个正文内容组至少包含：

- 短标题：7-14 字，带动词或判断。
- 判断句：说明问题、机会、原因或结论。
- 2-3 条支撑：事实、数据、案例、对象、周期、责任、动作。
- 标签：指标、风险、动作、来源或口径。

没有数据时不要编造数据，也不要缩成口号。`需补充`、`待补充`、`示意`、
`合理推断`、`预计` 只能出现在内部修补清单或明确的证据缺口页；常规最终 PPTX 正文
不得保留这些草稿态表达。证据不足时先补证据；补不了则改成“风险边界/假设条件/待用户确认”
等明确口径，或停止询问用户。

证据类内容先压成 `claim / evidence / implication` 三个短槽再填进版式，不要把素材摘要长句
原样粘进卡片：

- `claim`：本组要证明的判断，短标题或一句判断句。
- `evidence`：托住判断的事实、数据、案例、对象、周期或责任，给短语而非整段。
- `implication`：这条证据说明什么影响、机制或下一步。

## 容量与换行

填槽前先按字符容量裁剪文本，超出就拆成多行独立 `<text>`（逐行显式 y）或压成短语，禁止靠缩字号硬塞：

- 卡片正文每行 ≤ 22-26 个中文字符；超出必须拆成多行独立 `<text>`（逐行显式 y）或改写为更短的短语——多行不要用带 `x/y/dy` 的 `<tspan>`；同行内强调才用内联 `<tspan>`（仅覆写 fill/font-weight/font-size）。
- 卡片短标题 ≤ 12-14 个中文字符；判断句 ≤ 一行，放不下先改写不靠换行掩盖。
- 4 卡横排：每卡标题 ≤ 12 个中文字符，正文最多 2 行、每行 ≤ 18-20 个中文字符；
  装不下时先压短语、减条数，仍装不下改 2x2 或上下双区，不裁断第 3/4 卡。
- 右侧列表项：标题 ≤ 18 个中文字符；解释句拆成两行或压成短语，不放素材长摘要。
- 同一结论框/卡片内不要把字号差距过大的两句（如 30px 强调句 + 22px 解释句）挤在同一行或同一
  baseline：强调句单独成行，解释句另起一行并预留行距，避免强调句下压出框、与解释句重叠。

来源说明最多一句话，整页最多一个 source-note / `evidence-source`；视觉上可放在页脚区域
/ 内容区底部，但不要把来源扩成 `footer`、多行脚注或压住主体内容的说明条。

## 视觉说明

高密度不是堆字。用卡片、指标胶囊、动作条、对比标签和来源脚注承载信息。

内容偏少时不要缩在上半页交差：按 `contract-layout-density.md` 的铺满纪律放大字号、
增大卡片、拉开留白，把版面撑到画布主要区域；底部/右侧大面积连续空白是必改级问题。

## SVG说明

每个内容组都应有独立 `<g id="content-group-N">`。输入有 N 张卡、N 个步骤、N 个字段，
SVG 也要有 N 个对应文本组。
