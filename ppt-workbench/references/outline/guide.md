# PPT 大纲处理

把主题、散点笔记、现有大纲或已整理材料组织成能讲清楚的整册或局部结构。默认交付可阅读、可编辑的文字或 Markdown，不要求 JSON、Foundation 字段、工作流状态或确认步骤。

## 判断顺序

1. 从当前请求识别主题、受众、使用场景、沟通目标和大致篇幅。只有缺失信息会实质改变结构时才提问。
2. 先写整册 contract：`thesis`、`audience_decision`、`evidence_ladder` 以及指标、产品、工件、阶段、Owner 的 canonical 清单，再选择适合的叙事顺序，例如现状到判断再到行动、问题到原因再到方案、目标到差距再到路径、主张到证据再到决策。页数已经定下时不改页序。每一页按 [叙事与形状](narrative-shape.md) 标 `thesis` / `proves` / `dominant` / `label`，让首页和末页说同一句判断，中间页只证明这句里的半句，并能接入 `claim→evidence→action→validation→decision`。
3. 接受并保留用户已有大纲中有价值的结构。调整时说明关键合并、拆分、换序或删减理由，不为套模板重写一切。
4. 每个正文页先用人话写清谁、场景、问题和动作。再至少包含结论性标题、唯一 `primary_claim`、`proves`、`dominant`、2–3 个支撑证据或案例、证据状态与边界、必要的图表/图片建议和下一步动作。它们是大纲阶段的最小内容合同，后续 page spec 不得用通用默认值代替。人话字段见 [大纲方法参考](outline-method.md)。
5. 证据不足时使用“待核实”“建议补充”或明确假设，不把推测写成既定业务事实。封面、目录、章节页等固定页不强行补数据。
6. 检查页与页之间是否递进、对照或因果清楚，是否存在重复页、空泛标题、孤立章节、内容过载或一页只讲一个口号。
7. 按用户指定格式交付；未指定时使用简洁 Markdown。用户可以直接修改和交给任意制稿工具，无需额外确认流程。

## 常见任务

- **从零新建：** 先给出总论点与章节逻辑，再展开页序。只有一句主题时可以形成待讨论草案，但不编造数据、客户事实或实施进度。
- **调整现有大纲：** 优先修复论证顺序、重复、缺证据和页容量，保留用户明确要求的章节、页名和页数约束。
- **压缩：** 合并证明同一结论的页面，删除背景性重复，保留决策所需证据；不能只删标题而把内容暗中塞进其他过载页面。
- **扩展：** 只有现有页面承担多个独立结论或证据类型时才拆页；新增页要写清其在整册中的作用。
- **局部大纲：** 可只处理一章、几页或某段，不要求补成完整 deck。

需要更细的证据缺口、页级内容深度或结构检查时，读取 [大纲方法参考](outline-method.md)。历史来源及许可状态见 [来源说明](source-and-license.md)；其中 Ubrio 的双文件、工具和阶段指令仅供溯源，不是本技能要求。

## 边界

- 不强制调用素材整理技能；输入足够时直接完成大纲。
- 不派发页面任务，不选择最终版式，不生成、合并或导出 PPTX。
- 不隐式联网。需要时效性事实或公开来源且用户授权时，才使用宿主提供的检索能力并保留出处。
- 不静默覆盖用户现有文件；写文件时默认另存，覆盖必须有明确授权。
