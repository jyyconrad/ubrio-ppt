## 逐图复刻：先解释，再绑定内容

本家族的主要复用资产是[固定复杂组件库](complex-components.md)：先固化矩阵、时间轴、卡片、网络、金字塔、雷达和复合图表等组件，业务调用只替换数据。以下32页是这些组件的组合样例，承担整页叙事与原图视觉校准，不是唯一的复用粒度。

用户要求一样版式/风格/信息密度/视觉感受，或普通请求的材料恰好匹配复杂构图时，按本节工作。前一种以对应原图为视觉基准，后一种先判断内容能否支撑其结构；不能把所有页面改成五种抽象骨架。

1. **先确定业务问题。** 用一句话回答读者看完要理解或决定什么。例如R10要同时检查效率与质量，所以上部是两组同规格微图；下部从偏差走向五层诊断，右端给整改出口。R19要解释自增强关系，所以八节点必须闭环，并保留两条局部反馈；并列卡无法表达同样判断。逐图理由和文字分工见[32页设计推理](blue-dense-32-design.md)，这是基于图片的推断，不代表已知原作者意图。
2. **按信息关系选资源。** 运行`python3 scripts/svg/build_reference_page.py --list`，从问题和材料选择R资源；用`--describe R编号`读取业务问题、阅读顺序、文字角色、必要关系与内容容量，然后实际打开返回的包内原图。周复盘需六周序列/偏差/Owner/行动/根因树；因果网络需节点、Owner和明确边清单；遗憾页需四象限、评分和分支。材料不足时保留未知或减少交付范围并说明，不能偷用样例数据填满。
3. **文字按职责搭配。** 标题给唯一主判断，区块题定义证据角色，标签压缩重复字段，正文给事实/解释/动作，数字作为有口径的证据焦点，洞察给推论或取舍。它们不能层层重复标题。按选定资源的字段和固定容量写`content.json`；正文用短句保留信息点，标题过长先改判断句，不改变原图区域或用小字硬塞。
   授权合成材料也要先确定一套含义一致的业务数据：序列分类写季度、月份或真实比较对象，指标名/公式/单位/数值互相对应，趋势解释由这些值推出；人数与网络节点数对应。不能把动作短句批量轮换为图表分类，也不能将随机数、日期、百分比和业务名词逐槽拼接。通用动作和工件名称可以复用；业务事实按本次明确数据绑定，未知项保持未知。六图看板的微图分类有固定容量，详见组件目录，长解释移到正文。
4. **先通过合同，再编译具体构图。** 多页任务将每套主题的manifest和完整page specs（含`reference_id`与实际`reference_content`）放在同一输入中，按[参考整册入口](reference-deck-entry.md)调用`build_reference_deck.py`。该入口在首个render前调用既有整册/gold检查，绑定全部实际内容并检查容量；通过后从同一批内存规格生成gold起始SVG、参考最终SVG、native sidecar和PPTX，保留输入摘要、适配说明和前置报告。Agent写业务结论与证据，脚本只固定执行顺序及几何。单页构图研究/授权样例仍可用`build_reference_page.py --reference-id R编号 --content content.json --output-dir 当前页目录`，其编译成功不代表整册或语义验收。
5. **渲染与核对。** 对最终SVG走`write_svg.py → validate_svg_drawingml.py → render_svg_drawingml.py`；特殊画布用`--canvas-format auto`保留原比例。原生表/图的几何取实际PPT尺寸，不按16:9强制缩放。逐张读取最终预览与原图，核对区域占比、组件/节点/行数、连线方向、字体层级、颜色编码、文字容量、数字焦点和收口。裁切页复用当前R10的数据与组件，只改变可见范围；不重新排版。

`--describe`默认不显示示例事实。仅在用户授权使用合成数据的演示/测试任务时使用`--example`，完整输入和产物会标为合成案例；真实业务任务必须显式填齐内容，缺字段或数组容量错误会报错，不静默混入默认值。用户明确要求原图同构时可复用其几何；一般结构迁移仍按材料适配，不能复制客户事实。

## 一个主观点，多区证据

`primary_claim` 仍只有一个。`dominant` 表示支撑它的**主要信息关系**，不是只能画一个矩形/一条线。参考图常在同页放 2–4 个相互依赖的证据区：背景/口径、机制或诊断、指标/案例、行动/洞察；它们可以上下叠放、左右联动或嵌在一个主网格内。第二排卡片只在它承担新证据角色时出现，不能重复第一排的标题与事实。

新增语义主体关系：`成效看板`、`诊断链`、`阶段路线`、`机制架构`、`决策矩阵`。原有 `不可比证据`、`流程断点`、`左右对照`、`门禁`、`决定章` 继续可用。选择关系看材料，不为迁就版式改写事实。`attached` 的 1–3 项是合同里的口径、限制和行动，不限制正文可见证据块的数量；可见块须层级分明并服务同一判断。

## 五种可组合骨架

以下是 1280×720 画布的区域预算，按内容与用户模板调整。先把证据装进区域，再定微型组件；区域名称不是每页必填的空卡。

| 关系 | 区域与阅读顺序 | 内容槽和适用条件 | 退化信号 |
| --- | --- | --- | --- |
| 成效看板 | 结论标题(约 10%) → 背景/口径窄带(10%) → 3–4 项举措(25%) → 3–5 个指标/小图(35%) → 推论/下一步(8%) | 每项指标写基准/当前、单位、期间、来源；举措写动作而非抽象词。指标与举措只能表述资料支持的关联，不擅自写因果。p4/p6/p10/p12。 | 五张等大数字卡 + 一句空泛口号；数字没有口径或与举措断开。 |
| 诊断链 | 现象或问题矩阵(35–45%) → 根因/等待/责任关系(20–30%) → 整改与验证(20–30%) | 至少区分观察事实、解释、建议、待验证；可用 2×2、三栏或偏差链。原因证据不足时用“待核实原因”，不画成实证因果。p5/p7/p10/p14。 | 三张平等的文字卡；原因、行动和目标同色同权重。 |
| 阶段路线 | 阶段箭头/轴(15–20%) → 2–4 列阶段单元(45–55%) → 出口条件/风险/责任(20–25%) | 每阶段至少有目标、动作、可核验产出、Owner/风险；目标和已完成用不同状态。p3/p13。 | 只有三个大箭头和稀疏文字，没有可验收条件。 |
| 机制架构 | 中央层级/链路/循环(45–60%) + 左右输入、职责或输出(20–35%) → 价值/护栏(8–12%) | 用方向箭头、关系线或层级说明接口，避免把网络换成并列卡。必要时用原生表格给工件/责任明细。p9/p15/`metric-network.jpg`/`experiment-cycle.jpg`。 | 仅有彩色盒子，关系只能靠听众猜。 |
| 决策矩阵 | 决策轴/条件(10–15%) → 可编辑矩阵或左右对照(55–65%) → 选择路径、Owner、复核条件(20%) | 真正的行列明细用 native table；左右判断仍可用两块面板。可逆性、影响、证据强度要就地标注。`ownership-matrix.jpg`、`遗憾最小化.jpg`。 | 手绘伪表格；色彩暗示赢家却没有标准或数据。 |

组合骨架时保留一个主体关系，其他区域提供证据与解释。例如“成效看板 + 底部诊断链”仍是 `成效看板`，底部链解释指标异常；不要把两个完整页面硬塞在一页。相邻内容页不要连续使用同一网格超过两页。没有足够材料填满参考图的槽位时，缩减模块或调整页数，不造数、不复制参考事实。

## 网格、颜色与文字容量

- 16:9 白底；四周常留 40–60px，标题占高约 10–14%，正文占 72–82%，结论/来源占余量。优先 12 列隐形网格、2×2、3 列、4 列、左 1/3+右 2/3、上 40%+下 60%；同级元素共用列线和 10–18px 均匀间距。卡片只是局部证据单元，不把整个页面切成同权重的浮卡。
- 白色和浅灰蓝为大面积底；标题与分区栏用深蓝 `#0B2E66`/`#0E4389`，关键数与箭头用中蓝 `#1D66B5`，浅承载面 `#EAF2FA`，正文深灰 `#243344`，边界 `#CDD7E3`。青绿、紫或红只作小面积语义分类/风险。避免满屏深蓝、渐变底、厚阴影和过圆卡片。
- 标题通常 36–44px，分区栏 19–22px，卡片题 16–19px，正文 15–18px，指标 28–42px，来源/口径 11–13px。正文对象至少约 11pt；只有来源/次级注释才可更小。高密度用关系和分组实现，字号不能连续缩到不可读。使用已安装的简体中文无衬线字体（优先 Noto Sans CJK SC 或可验证的等价字体），在 PPTX 对象和真实预览里核对，不能只信 manifest 声明。
- 一张内容页通常有 3–8 个主要模块、8–25 个可扫读信息点；每个卡/行保留一句判断或 2–4 条短证据，必要时用标签列、数字、箭头、图标替代重复句式。这是容量观察范围，不是填满配额；数据不足时保留真实空缺。
- 视觉导航要说明阅读顺序：深蓝分区栏、编号、同家族图标和带方向的连接符至少选择一种。小图嵌在对应证据区，关键系列深蓝，比较系列浅蓝/灰；单位、基准、期间、阈值与一句洞察就近放。可排序数据仍用原生表格，图表仍用原生槽位。照片只在证明实景/产品/案例时局部使用。

## 从规格到可编辑成品

1. 先定页级 `primary_claim`、证据状态、主关系和上述区域。用包内样例 `assets/examples/blue-dense/result-dashboard.svg` 看**实际可编辑对象和层级**，再按本页信息关系打开对应参考 JPG；不能把 JPG、样例数字或水印铺成整页。
2. `page_spec.json` 仍先走 `build_gold_svg_page.py --validate-only`，同时按 [两个校验面](content-visual-quality-gates.md#同一份规格两个校验面) 填齐整册所需字段；包内示例的 `deck-manifest.json` 和 `result-dashboard.page_spec.json` 可直接运行两层校验。指标逐项填 `evidence_type/claim_type/population/period/denominator/source_ref/limitation/on_metric_label`，没有数值指标时明确 `quality_targets.metrics_min: 0`，不能靠默认占位指标凑数。将 `groups` 写成 2–3 个支撑关系，每组保留证据/解释/行动。金标 builder 生成起始 `source.svg` 和必要的 native sidecar；当前 builder 的通用布局**不会自动实现上述复合网格**。
3. 在 builder 的 `source.svg` 基础上，把同一事实和对象重排为所选骨架，补上区块标题、编号/图标、局部指标/关系与来源。保持标题、主要证据和 native slots 的可编辑对象；若最终 SVG 与 builder 输出不同，保留两版及变更说明，不把“运行过 builder”冒充“最终构图已由 builder 完成”。新语义 `dominant` 只由整册合同接受，`check_shape_picture.py` 对其中大部分不做确定性图形证明，需人工读最终预览。
4. 按现有 `write_svg.py → validate_svg_drawingml.py → render_svg_drawingml.py` 落地，对最终 PPTX 运行 `inspect_pptx.py` 并渲染全页。字体、数字、对象、表格/图表标签、来源与证据状态以最终文件为准。不要把结构通过、字段齐全或预览可读合并成一个“已验收”。

## 逐页视觉验收

把候选页和打开的参考图并排看缩略图、100% 预览和远距版：

1. 15 秒扫读能指出结论、主证据、下一步或风险；标题是完整判断句，数值或可核验条件是第二焦点。
2. 至少两个证据区有明确关系（解释、前后、因果假设、输入输出、阶段或对比）；深蓝导航、正文、注释至少四级层次可辨。没有大面积无意空白，也没有所有卡片同权重。
3. 数据的基准、单位、期间和证据状态邻近数字；微图不是无数据的装饰。建议/目标和观察/事实不能画成同一实绩。
4. 对齐、间距、中文无衬线字体与参考图的紧凑白蓝灰语言相符；无重叠、截断、水印、整页图片和伪表格。页底收口提出行动、决策、风险或经验，不复述标题。

记录每页对照的参考文件、可观察的相似点、差异与取舍。`visual_review=performed` 只在实际读过最终预览后填写；未完成 PowerPoint 编辑往返就保持 `powerpoint_roundtrip=not_performed`。
